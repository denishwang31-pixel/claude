# 테니스매치 — 기능 명세 (UI 디자인용)

디자이너에게 넘기는 문서입니다. **이 앱이 무엇을 하고, 어떤 화면이 있고,
각 화면이 어떤 상태를 가지는지**를 적었습니다.

색·글꼴·간격 같은 시각 규칙은 별도 문서 `DESIGN.md` 에 있습니다.
이 문서는 **기능과 상태**를 다룹니다.

> 여기 적힌 것은 **실제로 구현되어 도는 기능**입니다. 계획이나 아이디어는
> 넣지 않았습니다. 화면 이름은 앱에 보이는 글자 그대로입니다.

---

## 1. 이 앱은 무엇인가

**테니스 동호회 운영 도구**입니다. 한 문장으로:

> 총무가 단톡방에서 손으로 하던 일 — 참석자 세기, 대진 짜기, 회비
> 걷기 — 을 앱이 대신한다.

### 쓰는 사람

- 주 사용자는 **40~60대 클럽 회원**입니다
- 많은 경우 **코트에 서서, 햇빛 아래서, 한 손으로** 봅니다
- 총무·회장은 집에서 앉아서 긴 작업(회비 정산, 대진 편성)을 합니다

이 둘은 요구가 다릅니다. **회원 화면은 한 번에 끝나야 하고, 운영 화면은
빠뜨림이 없어야 합니다.**

### 규모

| | |
|---|---|
| 화면 파일 | 47개 컴포넌트 + 8개 탭 화면 |
| 로직 모듈 | 46개 (`src/lib`) |
| 코드 | 약 30,000줄 |
| 자동 검사 | 27개 묶음, 약 5,000건 |

## 2. 역할 — 화면이 사람마다 다릅니다

**모든 화면 설계에서 가장 중요한 축입니다.** 같은 메뉴라도 역할에 따라
보이는 것이 다릅니다.

| 역할 | 권한 |
|---|---|
| **회장** | 전부 + 직책 임명 |
| **총무** | 운영 전반 + **회비·지출** |
| **운영진** | 일정·대진·회원 (회비 못 봄) |
| **리드** | **자기가 맡은 코트장만** |
| **회원** | 조회 + 본인 참석 체크 |

### 디자인할 때 주의할 점

- **한 사람이 여러 역할을 겸합니다** (운영진 + 화요일 코트 리드).
  배지를 하나만 그리면 안 됩니다 — `운영진 · 리드` 처럼 묶어 표시합니다
- **회비는 회장·총무만** 봅니다. 운영진에게는 메뉴 자체가 안 보입니다
- 회장에게는 **보기 모드 전환**이 있습니다 — "회원 눈에는 이 화면이
  어떻게 보이나"를 확인하는 기능입니다. 헤더에 지금 어느 모드인지
  항상 보여야 합니다

---

## 3. 코트장(venue) — 두 번째 축

클럽이 **여러 코트장**을 운영하는 경우가 많습니다 (화요일 염곡, 목요일
수도공고). 이건 단순한 필터가 아닙니다.

- 회원마다 **소속 코트장**이 있고, 일정·참석 투표가 그 단위로 갈립니다
- **리드**는 자기 코트장만 봅니다
- 회비도 코트장별로 따로 걷을 수 있습니다
- 코트장마다 면수·시간·타임 길이·**코트 이름**이 다릅니다

### 디자인 함의

- 목록형 화면 상단에는 **코트장 선택 드롭다운**이 있습니다 (홈·일정·대진)
- "전체 코트" 와 개별 코트장을 고를 수 있습니다
- ⚠️ **지금 무엇으로 걸러져 있는지가 항상 보여야 합니다.** 이게 안 보이면
  사용자는 빈 화면을 보고 "일정이 없네"로 잘못 읽습니다

## 4. 화면 지도

### 하단 탭 (5개)

| 탭 | 내용 |
|---|---|
| **홈** | 다음 모임 + 1탭 참석 + 바로가기 4개 + 내 기록 |
| **일정** | 주간 띠 / 목록 / 캘린더 · 모임 등록 |
| **대진** | 대진 편성 · 표 보기 · 결과 입력 |
| **레벨업** | 위쪽 칸 나누기 **원포인트 / 용품 / 코치** |
| **더보기** | 나머지 전부 (아래) |

**5개가 한계입니다.** 예전엔 용품·원포인트가 따로 있어 6개였고, 휴대폰에서
글자가 좁아졌습니다. 탭을 늘리고 싶어지면 기존 칸 안에 넣을 수 있는지부터
봅니다.

**「레벨업」 이름을 정한 이유** — 디자인에서 이름을 바꿀 때 지켜 주세요.
- 홈·일정·대진은 "우리 클럽", 레벨업은 **"나"** 입니다 — 내 테니스가 나아지는 것들
- **「레슨」을 탭 이름에 쓰지 않습니다.** 영업으로 읽혀 사람들이 안 들어옵니다.
  부담 없이 들어와 부족한 걸 보다가 레슨으로 이어지는 흐름이 목표입니다
- 「원포인트」는 좋은 말이지만 **부모 이름으로는 좁습니다** — 용품·코치와 같은 층입니다
- 영어 `Level Up` 은 한글 탭들 사이에서 혼자 튀어 광고처럼 보입니다
- **코치는 맨 뒤 칸.** 앞세우면 탭 전체가 레슨 광고로 읽힙니다
- 아이콘은 "오른다"(위 화살표). ▶ 재생 버튼은 "영상 모음"이라는 뜻이라 맞지 않습니다

**원포인트 화면 (시안 A「선반」)** — 명세: `docs/onepoint-redesign-A.md`
- 머리는 **칸 나누기 한 줄뿐**(레벨업 제목·부제 없음). 세 칸이 같은 머리를 씁니다
- 칸 나누기 → **검색창**(늘 보임) → 가로로 넘기는 **선반**:
  새로 올라온 영상 6개 · 저장한 영상 · 영역마다 한 줄(영상 없는 영역은 숨김)
- 영상이 적어도 **늘 선반 화면**(명세의 "5개 이하 줄 목록"은 뺐습니다 — 영상이 적은
  첫 단계에서 시안과 전혀 다른 화면이 나왔습니다). 영역이 하나뿐이면 「새로 올라온 영상」 줄은 숨깁니다
- 썸네일이 오기 전·없을 때는 **코트 그림**(시안의 빈 썸네일과 같은 모양)
- 영상은 **앱 안에서 재생**(WebView + 유튜브 IFrame API). 삽입 금지 영상은
  안내 + [유튜브에서 보기]. 메모의 「3분부터」 → [3:00부터 보기]
- 재생 중 앱 밖으로 나가는 길은 **[↗ 유튜브] 버튼 하나뿐**. 플레이어가 스스로 youtube.com·
  intent:// 로 가려 하면 막기만 합니다(예전엔 그걸 유튜브 앱으로 넘겨서, 보다가 뒤로가기를
  누르면 유튜브 앱이 튀어나왔습니다)
- **봤어요·저장**은 회원별(`onepointStates/{uid}`), 본인만 읽고 씀
- **올리는 사람: 앱 관리자 + 앱 관리자가 승인한 코치만.** 영상은 앱 전체 공용(`onepoint`).
  클럽 운영진은 못 올립니다(영상의 질을 지키려고). 코치는 자기 영상만 수정·삭제,
  「추천」은 앱 관리자만 — 규칙(firestore.rules)이 같은 것을 막습니다
- 코치가 올린 영상엔 코치 이름이 붙고, 재생 화면의 코치 한 줄이 **그 코치 화면**으로 바로 갑니다
- 예전 클럽별 영상(`clubs/{id}/tips`)은 앱 관리자 화면에 **[앱 전체로 옮기기]** 안내로 뜹니다
- ＋ → 등록 시트(oEmbed 로 제목 자동, 같은 영상 중복 막음), **길게 누르기** → 수정 · 추천 · 삭제
- 코치 한 줄은 **재생 화면 끝 · 영역 모아보기 끝** 두 곳만. 코치가 0명이면 없음.
  코치는 클럽 소속이 아니라 앱 전체(승인된 코치)라서 문구는 「등록된 코치 N명」
- 태블릿(폭 900 이상): 왼쪽 영역 목록(전체 포함) + 오른쪽 선반/격자
- 「레슨」이라는 말은 이 화면 어디에도 쓰지 않습니다

**용품 · 코치도 같은 틀** — 칸 나누기 → 검색창 → 가로 선반/칩 한 줄 → 줄 목록
- 용품: 새로 들어온 용품 + 카테고리별 선반(정사각 사진·이름·가격·추천·판매처), 전체 › → 카테고리 모아보기,
  검색(이름·설명·카테고리). 앱 관리자는 ＋ 로 등록, 길게 눌러 삭제(예전 ✕ 단추는 스크롤하다 잘못 눌림)
- 용품 카테고리: 라켓 · 스트링 · 그립 · **라켓 튜닝**(납 테이프·댐퍼·스트링 세이버) · **보호대**(무릎·손목·팔꿈치·테이핑)
  · 신발 · 의류 · 가방 · 공 · 액세서리(모자·손목밴드·볼 홀더) · 기타. 예전 '스트링·소모품'은 '스트링'으로 읽는다
- 용품을 누르면 바로 판매처로 가지 않고 **상세**(사진·가격·설명·**추천 이유**) → 아래 [○○에서 보기]로 판매처
- **추천 이유**(`gearPicks/{상품_사람}`): 승인된 코치, 운영진이 **인증한** NTRP 4.0 이상·구력 5년 이상 회원,
  앱 관리자만 쓴다(셀프 평가 NTRP 는 인정 안 함). 이름표는 「최소라 코치」「고수 · NTRP 4.5 · 구력 14년」.
  NTRP·구력·이름은 회원 문서에서 그대로 옮겨 적어야 규칙을 통과한다(부풀려 적기 방지). 기준은 gearView.js
- 코치: 지역 칩 한 줄(시·도 → 시·군·구), 코치 줄(얼굴·지역·소개·영상 수·레슨 타임), 상세는
  얼굴·소개 → [전화하기] → 영상(앱 안 재생) → 경력 → 레슨 시간 → 레슨 코트. 「코치로 등록」은 맨 아래로

### [더보기] 안의 메뉴 — 4개 묶음 + 1개 (앱 운영자)

분류 기준은 **"누구의 것인가"** 입니다.

| 묶음 | 메뉴 |
|---|---|
| **내 활동** | 약관·개인정보 / 내 회비 / 내 기록·랭킹 / NTRP 등급 |
| **클럽 활동** | 클럽 대회 / 클럽 교류전 / 참가투표 / 게시판 / 회원 목록 |
| **찾아보기** | 게스트 모집 / 코트 검색 / 대회 찾기 |
| **클럽 운영** *(운영진만)* | 가입 신청 / 클럽 초대 / 출석 / 회비·지출 / 입금 대사 / 회비 알림 / 결산·회계보고 / 총무 인수인계 / 코트장 관리 / 커플·고정 페어 / 대진 설정 / 클럽 설정 |
| **앱 운영** *(앱 운영자만)* | 코치 승인·광고비 / 앱 운영 관리 |

> 메뉴가 많습니다. **이걸 어떻게 덜 무섭게 보이게 하느냐**가 디자인의
> 주요 과제 중 하나입니다. 지금은 묶음 제목 + 한 줄 설명으로 처리합니다.

## 5. 진입 흐름 (온보딩)

```
앱 실행
  │
  ├─ 로그인 안 됨 ──────→ [로그인]
  │                         ├─ 구글로 시작하기
  │                         ├─ 이메일 (로그인 / 회원가입)
  │                         └─ 계정 없이 둘러보기
  │
  ├─ 로그인됨 + 클럽 없음 ─→ [클럽 찾기/만들기]
  │                         ├─ 새 클럽 만들기 → 홈
  │                         ├─ 초대코드로 가입 → 홈
  │                         ├─ 비밀번호로 가입 → 홈
  │                         ├─ 검색 → 가입 신청 → (승인 대기) → 홈
  │                         └─ 나중에 하기 → 홈(제한 모드)
  │
  └─ 로그인됨 + 클럽 있음 ─→ 홈
```

### 상태별 화면

| 상태 | 무엇을 보여 주나 |
|---|---|
| 승인 대기 | 대기 안내 + 신청한 클럽 이름. **승인되면 자동으로 넘어감** |
| 거절됨 | 거절 안내 + 다시 찾기 |
| 클럽 없이 둘러보기 | 제한 안내 + [클럽 찾기] + **다른 클럽 공개 글** + 앱 정보 |

### 로그인 화면 구성 (현재)

1. 코트 사진 히어로 + 로고
2. 소셜 로그인 버튼 (준비된 것만 — 지금은 구글 하나)
3. **또는** 구분선 + [이메일로 계속하기] 접기 버튼
4. 이메일 폼 (로그인/회원가입 탭, 약관 체크, 비밀번호 재설정)
5. [계정 없이 클럽 둘러보기]
6. 기능 3종 소개 띠

> ⚠️ **준비 안 된 소셜 버튼은 그리지 않습니다.** 눌러도 안 되는 버튼이
> 가장 나쁩니다. 그래서 시안에 카카오·네이버·애플이 있어도 지금은 구글
> 하나만 나옵니다.

## 6. 핵심 흐름 — 이 앱의 뼈대

### 6-1. 일정 → 참석 → 대진 → 결과

```
[운영진] 모임 등록  ──┐
                      ↓
              자동 알림 "새 모임"
                      ↓
[회원]   참석 / 불참 누르기
                      ↓
        (N일 전) 자동 "투표 요청" → 아직 안 누른 사람에게만
                      ↓
[운영진] 대진 자동 작성 ─→ 인원 부족하면 게스트 모집글
                      ↓
              자동 알림 "대진표 발표" → 참석자에게
                      ↓
[뛴 사람] 점수 입력 → [상대 팀] 확인 ──→ 확정 · 랭킹·전적 반영
                      (확정 후 수정은 운영진만)
```

**이 네 단계가 앱의 중심축입니다.** 다른 모든 기능은 여기에 붙어 있습니다.

### 6-2. 참석 응답은 두 값뿐

**참석 / 불참.** "미정"은 **의도적으로 없앴습니다.**

> 미정이 있으면 확실하지 않은 사람이 전부 거기로 몰립니다. 고르기 제일
> 편하고 아무 책임도 안 지는 칸이기 때문입니다. 그러면 총무는 몇 명이
> 오는지 모른 채 코트를 잡고, 결국 단톡방에서 한 명씩 다시 묻게 됩니다.

화면에 나오는 집계는 **참석 / 불참 / 미응답** 세 가지입니다.
(예전에 저장된 '미정' 응답은 미응답으로 셉니다.)

### 6-3. 참석 체크 지점이 세 곳

같은 동작을 세 군데서 할 수 있습니다. 회원이 하는 일의 대부분이 이
한 번의 응답이라, 어디서든 되게 했습니다.

1. **홈** 다음 모임 히어로 카드 — 큰 버튼 2개
2. **홈** 예정 일정 목록 — 각 줄에 작은 버튼 2개
3. **일정** 탭 모임 상세

⚠️ 이미 응답한 뒤에도 **버튼 형태**로 바꿀 수 있어야 합니다. 텍스트
링크로 두었더니 아무도 눌리는 줄 몰랐습니다.

## 7. 화면별 기능 상세

### 7-1. 홈

| 구역 | 내용 | 조건 |
|---|---|---|
| 코트장 드롭다운 | 전체 / 개별 | 코트장 2곳 이상일 때 |
| **다음 모임 히어로** | D-day · 날짜/시간 · 장소 · 날씨 · 참석 집계 · 1탭 응답 | 예정 모임 있을 때 |
| 바로가기 4개 | 일정·투표 / 대진·점수 / 게시판 / 게스트 모집 | 항상. 각각 실제 숫자 한 줄 |
| 클럽 운영 | 회원·가입신청·출석·회비·입금대사·회비알림 | 운영진 이상 |
| 다가오는 대회 | 최대 3개 | 있을 때 |
| 예정 일정 목록 | 최대 6건 + 참석 버튼 | |
| 내 기록 | 경기 수·승률 등 | |
| 보기 모드 전환 | 회원/리드/운영진… 눈으로 보기 | 회장만 |

**빈 상태**: 모임이 하나도 없으면 "예정된 모임이 없습니다" + 운영진에게는
[＋ 새 모임] 안내.

### 7-2. 일정

세 가지 보기:

- **주간 띠** — 오늘부터 7일. 모임 있는 날에 점. 누르면 그날만
- **목록** — 다가오는 순
- **캘린더** — 월 전체

모임 카드: 날짜·요일·**시작~종료 시간**·장소·면수·타임 수·참석 집계.

**모임 등록 폼** (운영진):

| 칸 | 비고 |
|---|---|
| 코트장 | 고르면 아래가 자동으로 채워짐 |
| 날짜 | 오늘 이후 |
| 시작 / 종료 시간 | **종료를 바꾸면 타임 수가 자동 계산** |
| 코트 표면 | 선택 |
| 경기 종료 점수 | 게임 수 |
| 랭킹에 반영 | 스위치 |
| 코트 면수 / 타임 수 | 자동값을 직접 고칠 수 있음 |
| 장소 | |
| **반복** | 정기 모임이면 기한까지 한 번에. **몇 회 생성되는지 미리 표시** |

### 7-3. 대진

가장 복잡한 화면입니다. 총무가 앉아서 하는 작업.

**상단**: 코트장 드롭다운 → 날짜 가로 스크롤 → 그 모임의 대진

**내 경기 히어로** (회원용): 내가 뛰는 다음 경기 하나를 크게.
`3타임 · B 코트 · 10:40~11:20 · 김철수(나) · 이영희 VS …`

> 회원이 알고 싶은 것은 표 전체가 아니라 **"내가 몇 타임 몇 번 코트에서
> 누구랑 하는가"** 하나입니다. 전체 표에서 자기 이름을 찾는 일을 없앱니다.

**편성 방식**: 일반 편성 / KDK(개인전)

**경기 방식**: 복식 / 단식 / 혼합(타임마다 지정)

**대진 표(그리드)**: 가로 = 코트, 세로 = 타임.
- 코트 헤더는 **그 코트장이 정한 이름** (A·B·C 또는 9·10·11)
- 성별 색 구분, 내 이름 강조, 내 경기 강조
- 경기를 누르면 점수 입력 — **뛴 사람만**. 확인 대기 중이고 내가 상대 팀이면 확인창이 뜬다
- 점수 칸은 세 상태: **기록전 / "6:3 확인"(확인 대기, 주황) / 6:3(확정, 초록)**.
  확인 대기를 기록전과 똑같이 그리면 아무도 확인하러 오지 않는다 — 디자인에서 반드시 구별할 것
- 내가 확인해 줘야 할 경기는 화면 **맨 위** 주황 카드로 모인다

**출석 그리드**: 사람 × 타임. 뛰는 타임에 코트 이름, 쉬는 타임에 "휴"

**부족 안내**: 인원이 모자라면 무엇이 몇 명 부족한지 + 바로 게스트 모집글

**수기 편집**: 드래그로 사람 이동. 같은 타임 중복은 막음

**명단 변동 감지**: 참석자가 바뀌면 "대진과 명단이 다릅니다" + 영향받는
경기만 골라 고치기

### 7-4. 회원 목록

- 회원 카드: 이름·성별·조·직책 배지·소속 코트장
- 누르면 프로필 수정 / 직책 변경
- **회원 추가 (오프라인 등록)** — 앱을 안 쓰는 분을 명단에 넣기
  - 이름 · 성별 · 클럽 내부 조 · 테니스 시작일 · 직책 · **소속 코트장**
  - ⚠️ 소속 코트장이 비면 일정·투표가 엉뚱하게 갑니다. 등록 시점에
    받는 것이 가장 안 빠집니다

### 7-5. 코트장 관리

코트장마다: 이름 · 면수 · 시작/종료 · **코트 이름(면마다)** · 타임 길이 ·
리드 담당자 · 주소 · 회비 별도 설정 · 알림 별도 설정

**코트 이름**이 중요합니다. 기본은 1·2·3 이지만 현장은 A·B·C 이거나
9·10·11 입니다. 표와 현장이 다른 말을 하면 사람들이 표를 안 봅니다.

### 7-6. 회비 (회장·총무)

- **잔액 히어로 카드** — 총무가 제일 먼저 보는 숫자
- 수입 / 지출
- 회원별 납부 체크
- 지출 기록 (날짜·코트장·항목·금액·메모)
- **입금 대사** — 은행 거래내역 붙여넣기 → 이름 매칭 → 별칭 등록
- **회비 알림** — 미납자에게 개별 발송
- **결산·회계보고** — 총회 자료
- **총무 인수인계** — 권한만 이전, 기록은 남음

### 7-7. 게시판

말머리 5종 + 공개 범위.

| 말머리 | 누가 쓰나 | 기본 공개 | 날짜 필수 | 지나면 |
|---|---|---|---|---|
| 공지 | 운영진 | 우리 클럽만 (고정) | | |
| 코트 양도 | 누구나 | 모든 클럽 | ✅ | 흐려지고 맨 아래 |
| 대회 멤버 모집 | 누구나 | 모든 클럽 | ✅ | 흐려지고 맨 아래 |
| 회원 모집 | 누구나 | 모든 클럽 | | |
| 자유 | 누구나 | 우리 클럽만 (고정) | | |

- 말머리 칩에 **글 수**를 같이 표시
- 다른 클럽 글에는 **클럽 이름 배지**
- 남의 클럽 글에는 댓글 칸을 그리지 않음 (권한이 없어서)
- **클럽이 없는 사람에게도 공개 글이 보입니다** — 회원 모집 글을 봐야 할
  사람이 바로 그 사람들이기 때문

### 7-8. 게스트 모집 (전체 공개 게시판)

모든 클럽이 함께 보는 하나의 게시판.

**모집글**: 날짜·시간·장소(우리 코트장에서 선택)·지역(시/도→시·군·구)·
남/여 모집 인원·**코트비(직접 입력)**·공개 범위·추가 조건

**신청 카드**: 신청자 목록, 성별 조건이 맞으면 **매칭 배지**,
운영진이 **확정**하면 그 모임 게스트로 자동 등록 → 대진에 포함

⚠️ 코트비가 없으면 **"코트비 문의"** 로 표시합니다. `0원`으로 적으면
공짜라는 뜻이 되어 현장에서 다툼이 납니다.

## 8. 알림 설계

## 9. 디자인할 때 지켜야 할 것

### 9-1. 야외에서 보는 화면

- 본문 **15px 이상**, 굵기는 medium(500) 이상
- 터치 영역 **48px 이상**, 주 행동 52px, 입력칸 56px
- 순백 배경은 햇빛에서 눈이 부십니다 (`#F8FAFC` 사용)
- 얇은 회색 글씨는 밖에서 거의 안 보입니다

### 9-2. 없는 숫자를 지어내지 않습니다

이 원칙 때문에 시안에서 뺀 것들이 있습니다:

- "14/16명 정원" 게이지 — **정원 필드가 없습니다**
- "케미 85%" — 그런 계산이 없습니다
- "전국 520+ 클럽" — 사실이 아닙니다
- "실시간 자동 입금 승인" — 붙여넣기 방식이고 자동 승인이 없습니다

> 첫 화면에 없는 기능을 적으면, 그걸 기대하고 들어온 사람이 못 찾습니다.
> 돈을 다루는 화면에서는 더 위험합니다 — 없는 동작을 믿고 확인을
> 건너뜁니다.

**분모가 없으면 진행률 막대를 그리지 않습니다.**

### 9-3. 눌러도 안 되는 버튼을 만들지 않습니다

- 준비 안 된 소셜 로그인 → 버튼 자체를 안 그림
- 권한 없는 글의 댓글 칸 → 안 그림
- 못 하는 이유가 있으면 **버튼 대신 그 이유를 적습니다**
  (예: "염곡 소속이 아니어서 참석 체크는 하지 않습니다")

### 9-4. 상태가 보여야 합니다

- 지금 어느 코트장으로 걸러져 있는가
- 지금 어느 보기 모드인가 (회장)
- 이 글이 어디까지 공개되는가
- 지난 글인가

### 9-5. 되돌릴 수 없는 일은 조심스럽게

- 글은 **지우지 않고 흐리게** 합니다 (지난 양도글 등)
- 공개 범위는 **모르면 좁은 쪽**으로 읽습니다
- 인수인계는 **권한만** 넘기고 기록은 남깁니다

정직하게 적습니다. 디자인으로 해결할 수 있는 것이 섞여 있습니다.

5. **앱 아이콘이 아직 예전 것**입니다
6. 빈 상태(empty state) 그림이 없습니다 — 지금은 글자만
7. 로딩 상태가 대부분 단순 스피너입니다
8. 교류전·리그 화면의 코트 표기가 아직 숫자입니다 (정기 모임은 이름)

## 오프라인 회원 → 앱 가입 회원 합치기

오프라인으로 등록해 쓰던 사람이 나중에 앱에 가입하면 한 사람이 둘로 갈라진다.
**회장·총무**가 합치면 서버가 클럽 안 모든 기록(참석·대진·점수·회비·입금자명 연결 등)에서
오프라인 아이디를 새 계정으로 바꿔 쓰고 오프라인 회원을 지운다.

- 어디서: 회원 목록 맨 위 **「앱에 가입한 오프라인 회원」**(이름이 같은 짝을 권함) 또는
  오프라인 회원을 눌러 **「앱 회원과 합치기」**에서 직접 고르기. 동명이인이 있을 수 있어 자동으로 합치지 않는다
- 겹치는 칸(둘 다 같은 모임에 참석을 누름 등)은 **앱 계정 쪽**(본인이 누른 것)을 남긴다
- 회원 정보는 앱 계정에 **비어 있는 칸만** 채운다(운영진 인증 NTRP, 구력, 조 등). 권한·상태는 옮기지 않는다
- 서버 함수(`onMemberJobCreated`)가 한다 — **Cloud Functions 배포가 필요**. 합치며 다시 쓴 모임에는
  `mergeOp` 표시를 남겨 참석 변경 알림이 무더기로 가지 않게 막는다
- 판단: `functions/mergeMember.js`(아이디 바꾸기·회원 칸 합치기), 권유: `src/lib/mergeMember.js`

## 회비 관리 (홈 · 더보기 한 칸)

- 홈 「클럽 운영」의 회비 아이콘은 **회비 관리** 하나. 들어가면
  1. **현황판**: 기간(월납/연납, 최근 달) · 청구 단위 · **납부 · 미납 · 미수금** · 납부율 · 회비 수입 − 지출 = 잔액
  2. **회비 미납 관리**(펼치기): 확인 요청 → 알림 단계(발송) → 납부 안내 설정 → **개인별 납부 현황**(칸을 누르면 납부↔미납 바로 바뀜, 이름순 고정 — 누른 줄이 움직이지 않게)
  3. **회비 지출 관리**(펼치기): 코트장 거르기 · [+ 지출 입력] · 이 기간 지출 목록 · 삭제
  4. 일회성 정산(대회·회식) — 맨 아래 작은 메뉴
  두 메뉴는 따로 열고 닫는다. 기간·청구 단위는 현황판에서 정하고 아래가 전부 따른다
- 「회비 알림」 → **「회비 현황」**으로 이름을 바꿨다. 「입금 대사」는 홈에서 뺐다(더보기에 남김).
  은행 내역 붙여넣기 일괄 매칭도 같은 이유로 회비 관리에서 뺐다(입금 대사 화면에 있음)
- 회비 문서는 회비 관리가 직접 구독한다 — 예전 화면은 연납일 때 월 문서를 읽고 연 문서에 써서 체크가 안 보였다
- 알림 단계의 [발송]은 **서버가 실제로 보낸다**(pushJobs · type 'dunning'). 예전엔 기록만 하고
  알림이 안 나갔다. 대상(미납자)과 문구는 서버가 다시 계산한다
- **최종 안내는 여러 번**(하루 한 번) 보낼 수 있다. 버튼 아래에 최근 발송일·횟수. 자동 단계는 한 번만
- 숫자 계산은 `src/lib/feeView.js`(검사 scripts/test-feeview.mjs)
