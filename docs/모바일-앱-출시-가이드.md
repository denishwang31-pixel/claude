# 가계부 앱 — iOS / Android 스토어 출시 가이드 (하나부터 열까지)

이 문서는 **현재 이 저장소의 가계부 자동화 앱**(React + Vite 클라이언트, Express + tRPC 서버, MySQL)을
그대로 활용해서 iOS 앱스토어와 Google Play에 출시하는 전체 과정을 순서대로 설명합니다.

> **핵심 요약**: 지금 앱은 "내 PC에서 서버와 DB를 켜야 도는 웹앱"입니다.
> 모바일 앱이 되려면 ① 서버와 DB를 인터넷(클라우드)에 올리고,
> ② 웹 화면을 **Capacitor**라는 도구로 앱 껍데기에 넣고,
> ③ 애플/구글 개발자 계정으로 심사를 받아 올리면 됩니다.
> 코드를 새로 짤 필요는 거의 없고, 지금 React 코드를 그대로 씁니다.

---

## 0단계. 전체 그림과 방식 선택

### 왜 Capacitor인가?

| 방식 | 설명 | 판단 |
|---|---|---|
| **Capacitor (추천)** | 지금의 React 웹앱을 그대로 네이티브 앱 껍데기에 넣음 | 코드 재사용 100%, 스토어 등록 가능 |
| React Native / Flutter | 화면을 처음부터 다시 개발 | 전면 재개발 필요 — 비추천 |
| PWA (홈 화면 추가) | 앱 설치 없이 브라우저로 | 가장 쉽지만 **앱스토어에 못 올림** |

지금 클라이언트가 이미 React + Vite로 잘 만들어져 있으므로 **Capacitor**가 정답입니다.
Recharts 차트, 엑셀 업로드, 탭 UI 전부 그대로 동작합니다.

### 준비물 (미리 확보)

| 항목 | 비용 | 비고 |
|---|---|---|
| Apple Developer Program | **연 $99 (약 13만원)** | https://developer.apple.com — 가입 승인 1~2일 |
| Google Play Console | **최초 1회 $25** | https://play.google.com/console |
| **Mac 컴퓨터** | — | iOS 빌드는 Xcode(맥 전용) 필수. 없으면 9단계의 클라우드 빌드 참고 |
| 클라우드 서버 + DB | 월 0~1만원 | 2단계 참고 |
| 개인정보처리방침 페이지 URL | 무료 | 양쪽 스토어 모두 **필수** (금융 데이터라 특히 중요) |
| 앱 아이콘 원본 | — | 1024×1024 PNG 1장이면 자동 생성 가능 |

## 1단계. 서버와 DB를 클라우드에 배포

지금은 `가계부실행.bat`으로 내 PC에서 서버(포트 3001)와 MySQL을 켜는 구조입니다.
앱 사용자는 내 PC에 접속할 수 없으므로, 서버가 **항상 켜져 있는 인터넷 주소**가 필요합니다.

### 1-1. 추천 조합

- **Railway** (https://railway.app) — Node 서버 + MySQL을 한곳에서. 설정이 가장 쉬움. 월 $5 정도.
- 또는 **Render**(서버) + **PlanetScale/Aiven**(MySQL)
- 국내 서비스가 편하면 **Cloudtype** (https://cloudtype.io)

### 1-2. 배포 절차 (Railway 기준)

1. Railway 가입 → New Project → **Deploy from GitHub repo** → 이 저장소 선택
2. 같은 프로젝트에 **MySQL 데이터베이스 추가** → 자동으로 접속 주소가 생김
3. 서버 서비스의 환경변수 설정 (`.env.example` 참고):
   ```
   DATABASE_URL=mysql://... (Railway가 준 주소)
   NODE_ENV=production
   SESSION_SECRET=아무도 못 맞출 긴 랜덤 문자열
   PORT=3001
   KAKAO_CLIENT_ID=... (카카오 로그인 쓸 경우)
   KAKAO_REDIRECT_URI=https://내서버주소/auth/kakao/callback
   DEV_AUTO_LOGIN=false   ← 반드시 false! (안 그러면 아무나 로그인됨)
   ```
4. 빌드 명령: `npm run build`, 시작 명령: `npm start`
5. 배포 후 테이블 생성: 로컬에서 `DATABASE_URL`을 클라우드 주소로 바꾼 뒤 `npm run db:push`
6. 브라우저에서 `https://내서버주소` 접속해 가계부가 뜨는지 확인

> **✅ 체크포인트**: 휴대폰 브라우저(LTE, 와이파이 끄고)에서 서버 주소로 접속해
> 엑셀 업로드까지 되면 1단계 성공입니다.

## 2단계. 앱용으로 코드 몇 군데 수정

Capacitor 앱은 화면을 `capacitor://localhost` (앱 내부)에서 열기 때문에,
"같은 주소의 서버"라는 가정이 깨집니다. 3곳을 고쳐야 합니다.

### 2-1. API 주소를 환경변수로 (`client/src/lib/trpc.ts`)

현재 `url: "/trpc"` (상대 경로) → 앱에서는 절대 주소가 필요:

```ts
const API_BASE = import.meta.env.VITE_API_URL ?? ""; // 웹 빌드에선 빈 값 = 기존 그대로

url: `${API_BASE}/trpc`,
```

앱 빌드 시엔 `.env.app` 파일에:
```
VITE_API_URL=https://내서버주소
```

### 2-2. 서버 CORS와 세션 쿠키 (`server/index.ts`)

앱(다른 출처)에서 세션 쿠키가 동작하려면:

```ts
app.use(cors({
  origin: ["capacitor://localhost", "http://localhost", "https://내서버주소"],
  credentials: true,
}));

// 세션 쿠키 설정에 추가:
cookie: {
  httpOnly: true,
  secure: true,
  sameSite: "none",   // ← 교차 출처에서 쿠키 전송 허용 (앱 필수)
  maxAge: 30 * 24 * 60 * 60 * 1000,
}
```

> iOS 웹뷰는 교차 출처 쿠키를 막는 경우가 있어, 문제가 생기면 Capacitor 설정에서
> 서버 주소를 앱 출처로 삼는 방법(아래 `capacitor.config.ts`의 `server.hostname`)이나
> 세션 대신 **토큰(Authorization 헤더) 방식**으로 바꾸는 것이 가장 확실합니다.

### 2-3. 로그인 방식 — 애플 심사의 최대 관문

- 카카오 로그인 콜백(`res.redirect("/")`)은 앱에서는 앱으로 돌아오지 못합니다.
  → 앱에서는 `@capacitor/browser`로 로그인 창을 열고, 커스텀 URL 스킴
  (예: `budgetapp://auth?token=...`)으로 앱에 복귀시키는 처리가 필요합니다.
- **애플 규정 4.8**: 카카오 같은 제3자 로그인이 있으면 **Apple로 로그인(Sign in with Apple)을
  반드시 함께 제공**해야 심사를 통과합니다.
- **가장 쉬운 우회**: 부부/가족용 앱이라면 소셜 로그인을 빼고
  **이메일+비밀번호(또는 초대 코드) 로그인**으로 바꾸면 애플 로그인 의무가 사라져 심사가 단순해집니다.

## 3단계. Capacitor 설치와 프로젝트 생성

프로젝트 폴더에서:

```bash
npm install @capacitor/core @capacitor/cli
npx cap init "우리집 가계부" "com.yourname.budget" --web-dir=dist/public
npm install @capacitor/ios @capacitor/android
```

- `com.yourname.budget`은 **앱 ID(번들 ID)** — 전 세계 유일해야 하며 **나중에 못 바꿉니다.**
  본인 도메인이 있으면 `com.도메인.budget`, 없으면 `io.github.깃헙아이디.budget` 형태 추천.

생성된 `capacitor.config.ts` 예시:

```ts
import { CapacitorConfig } from "@capacitor/cli";

const config: CapacitorConfig = {
  appId: "com.yourname.budget",
  appName: "우리집 가계부",
  webDir: "dist/public",
  server: {
    androidScheme: "https",   // 안드로이드에서 https 출처로 동작 (쿠키 문제 완화)
  },
};
export default config;
```

네이티브 프로젝트 생성:

```bash
npm run build          # dist/public 생성 (vite.config.ts의 outDir)
npx cap add android
npx cap add ios        # 맥에서만
npx cap sync           # 웹 빌드 결과를 앱 프로젝트로 복사
```

로컬 테스트:

```bash
npx cap run android    # 안드로이드 에뮬레이터/USB 연결 기기에서 실행
npx cap open ios       # 맥에서 Xcode 열기 → ▶ 실행
```

## 4단계. 앱 아이콘과 스플래시 화면

1024×1024 PNG 아이콘 1장(`resources/icon.png`)과
2732×2732 스플래시 1장(`resources/splash.png`)을 준비한 뒤:

```bash
npm install -D @capacitor/assets
npx capacitor-assets generate
```

→ iOS/Android 모든 해상도의 아이콘·스플래시가 자동 생성됩니다.
아이콘 제작은 Figma, Canva 등에서 하면 됩니다 (단순한 원화 ₩ 심볼 + 배경색이면 충분).

## 5단계. Android — 서명 키와 릴리스 빌드(AAB)

### 5-1. 서명 키(keystore) 만들기 — 한 번만, 영구 보관

```bash
keytool -genkey -v -keystore budget-release.keystore \
  -alias budget -keyalg RSA -keysize 2048 -validity 10000
```

> ⚠️ **이 파일과 비밀번호를 잃어버리면 앱 업데이트를 영영 못 올립니다.**
> 클라우드 드라이브 등 2곳 이상에 백업하세요. git에는 절대 커밋 금지.

### 5-2. 릴리스 빌드

`android/app/build.gradle`에 서명 설정을 추가하거나, Android Studio 메뉴
**Build → Generate Signed Bundle** 사용:

```bash
cd android && ./gradlew bundleRelease
# → android/app/build/outputs/bundle/release/app-release.aab
```

Google Play에는 APK가 아니라 **AAB 파일**을 올립니다.

## 6단계. Google Play Console 등록

1. https://play.google.com/console 가입 ($25, 신분증 확인 있음)
2. **앱 만들기** → 이름, 기본 언어(한국어), 앱/게임, 유료/무료 선택
3. **필수 양식 작성** (대시보드가 순서대로 안내):
   - 개인정보처리방침 URL ← **필수**
   - 데이터 보안 양식: "재무 정보(거래 내역)를 수집·전송함, 암호화됨(HTTPS), 삭제 요청 가능" 등 사실대로
   - 콘텐츠 등급 설문, 타겟 연령(18세 이상 권장 — 금융 앱)
   - 스토어 등록정보: 스크린샷(휴대폰 2장 이상), 512×512 아이콘, 1024×500 배너, 앱 소개 글
4. **비공개 테스트(중요!)**: 2023년 11월 이후 만든 **개인 개발자 계정**은
   **테스터 12명 이상이 14일간 연속 참여하는 비공개 테스트**를 거쳐야 프로덕션(정식 출시) 신청이 가능합니다.
   가족·지인·가계부 그룹 멤버들을 테스터 이메일로 초대하세요.
5. 비공개 테스트 → (14일 후) **프로덕션 출시 신청** → 심사 (보통 1~7일)

## 7단계. iOS — Xcode 빌드와 서명

**맥 + Xcode(앱스토어에서 무료 설치)가 필요합니다.**

1. Apple Developer Program 가입 완료 후 `npx cap open ios`
2. Xcode에서 프로젝트 선택 → **Signing & Capabilities** 탭:
   - Team: 본인 개발자 계정 선택
   - Bundle Identifier: 3단계의 앱 ID와 동일하게
   - "Automatically manage signing" 체크 → 인증서·프로비저닝 자동 처리
3. 실기기 테스트: 아이폰 USB 연결 → 상단 기기 선택 → ▶
4. 배포용 빌드: 상단 기기를 **Any iOS Device (arm64)** 로 → 메뉴 **Product → Archive**
5. Archive 완료 창에서 **Distribute App → App Store Connect → Upload**

## 8단계. App Store Connect 등록과 심사

1. https://appstoreconnect.apple.com → **나의 앱 → + 신규 앱**
   (이름, 번들 ID, SKU 입력)
2. **TestFlight**: 업로드된 빌드로 가족·지인에게 먼저 배포해 테스트 (이메일 초대, 최대 1만 명, 심사 없이 내부 테스터 100명)
3. **앱 정보 입력**:
   - 스크린샷: 6.7인치(1290×2796) 필수, 가능하면 6.5/5.5인치도
   - 개인정보처리방침 URL, **앱 개인정보 보호(누트리션 라벨)**: 수집 항목 사실대로 (금융 정보, 식별자 등)
   - 카테고리: 금융(Finance), 연령 등급 4+
4. **심사 제출 시 메모**: 심사원이 로그인할 수 있도록 **데모 계정(아이디/비번)을 반드시 제공**
   + 사용법 요약("은행 엑셀 파일을 업로드하면 자동 분류됩니다. 샘플 파일: ~") 첨부
5. 심사: 보통 24~48시간. 거절되면 사유가 오고, 수정 후 재제출하면 됩니다.

### 자주 걸리는 거절 사유 (미리 방지)

| 사유 | 예방책 |
|---|---|
| 4.2 최소 기능성 — "웹사이트를 감쌌을 뿐" | 앱답게: 파일 공유로 엑셀 받기, 스플래시, 오프라인 안내 화면 등 네이티브 요소 1~2개 추가 |
| 4.8 — 제3자 로그인만 있음 | Apple 로그인 추가 또는 이메일 로그인으로 전환 (2-3 참고) |
| 2.1 — 심사원이 로그인 불가 | 데모 계정 + 샘플 엑셀 파일 제공 |
| 5.1.1 — 개인정보 고지 미흡 | 개인정보처리방침에 수집 항목·보관 기간 명시 |

## 10단계. 출시 후 — 업데이트 루틴

코드를 고칠 때마다:

```bash
npm run build && npx cap sync
# Android: 버전 올리기 → android/app/build.gradle의 versionCode(+1), versionName
#          ./gradlew bundleRelease → Play Console에 새 AAB 업로드
# iOS:     Xcode에서 Version/Build 올리기 → Archive → Upload → 심사 제출
```

- 서버 쪽 수정은 심사 없이 Railway에 배포만 하면 즉시 반영됩니다.
  (화면 로직은 앱 안에 들어있으므로 앱 심사가 필요 — 급한 화면 수정은
  Capacitor의 라이브 업데이트 서비스(Appflow, Capgo)로 심사 없이 배포하는 방법도 있습니다.)
- 앱스토어/플레이스토어 리뷰 알림을 켜두고, 크래시 리포트(Play Console 자동 제공, iOS는 Xcode Organizer) 확인.
