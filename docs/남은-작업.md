## ⏳ FIX-07 · 키워드 자동분류를 컬럼으로 bake (P1, 난이도 상)
**왜 지금 안 했나**: 이 저장소 환경엔 실제 PostgreSQL이 없어 **마이그레이션 백필 + "결과 불변"을
라이브로 검증할 수 없음**. 성능 이슈(보안 아님)라 검증 없이 코어 읽기경로를 바꾸는 위험을 피함.
지금은 FIX-10 테스트로 분류 로직이 고정돼 있어 안전하게 착수 가능한 상태.

- **대상**: `server/db.ts` `autoMapSQL`/`buildEffectiveCategoryExpr`, `insertTransactions`, `runAutoMigrations`
- **목표**: 요청당 ~200KB SQL(31KB CASE ×6 인라인) 제거 → 집계 쿼리 경량화·인덱스 활용
- **접근**: `ruleCategory` 와 동일 패턴
  1. 마이그레이션에 `autoCategory varchar(64)` 추가 + 기존 행 백필
     (현재 `autoMapSQL` 순서 그대로: 뱅크샐러드 매핑 → 키워드 → 기타)
  2. `bakeAutoCategoriesForHashes(userId, hashes)` 신설, `uploadTransactions`·`addManualTransaction` 직후 호출
  3. `buildEffectiveCategoryExpr` = `COALESCE(customCategory, ruleCategory, "autoCategory", category)` 로 축소
  4. `generateRulesFromTransactions` 의 `autoMapSQL` 참조도 컬럼으로 교체
- **검증 필수**: Neon 연결 후 `npm test`(분류 26샘플) + 대시보드/카테고리별 수치가 bake 전후 동일한지 대조
- **Before/After**: 읽기마다 CASE 인라인 → 쓰기 1회 계산, 읽기는 컬럼 참조
