# 내가 직접 해야 하는 작업 (코드로 끝낼 수 없는 것)

앱 코드는 준비됐습니다. 아래는 **외부 계정·설정·심사**라 사용자가 직접 해야 하는 일만 모았습니다.
순서대로 하면 됩니다. (코드로 이미 끝난 건 여기 없음)

---

## 0. 준비물 (한 번만)
- [ ] **Apple Developer Program** 가입: https://developer.apple.com — 연 $99, 승인 1~2일
- [ ] **Google Play Console** 가입: https://play.google.com/console — 1회 $25
- [ ] **Mac + Xcode**(iOS 빌드 필수. 없으면 8-B의 클라우드 빌드)
- [ ] **개인정보처리방침 URL**(양 스토어 필수) — 8-1 참고

## 1. 데이터베이스(Neon) — 필수, 무료
1. https://neon.tech → GitHub로 가입
2. **Create project** → Region **Seoul/Tokyo**
3. **Connect** → **Pooled connection** 선택 + **Show password** → 접속 문자열 복사
   (형태: `postgresql://user:npg_xxx@ep-...-pooler.ap-...aws.neon.tech/neondb?sslmode=require`)
4. 이 문자열을 **`DATABASE_URL`** 로 사용 (2단계 배포 시 입력)
5. 로컬에서 한 번: `.env` 의 `DATABASE_URL` 을 이 값으로 바꾸고 → `npm install && npm run db:push`
   → Neon 대시보드 **Tables** 에 `users/transactions/budgets/groups...` 보이면 성공

> 상세 클릭 가이드는 `docs/모바일-앱-출시-가이드.md` 1-2절.

---

## 2. 서버 배포 (Render 또는 Railway) — 필수
1. Render/Railway 가입 → **Deploy from GitHub repo** → 이 저장소
2. **환경변수** 설정 (아래는 이번 보안 수정으로 **필수/변경된 것 포함**):
   ```
   DATABASE_URL = (1단계 Neon 문자열)
   NODE_ENV = production
   SESSION_SECRET = (긴 랜덤 문자열)   ← ★필수. 없으면 서버가 안 뜸(의도된 안전장치)
   DEV_AUTO_LOGIN = false               ← ★반드시 false
   CLIENT_ORIGINS = https://내-웹도메인 (웹으로도 접속시)
   AUTH_SUCCESS_REDIRECT = /            (앱 딥링크 쓰면 그 스킴)
   ```
   `SESSION_SECRET` 만들기: 터미널 `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
3. 빌드: `npm run build` / 시작: `npm start`
4. 배포된 `https://내서버주소` 접속 → 로그인 화면 뜨면 성공
5. 휴대폰(LTE)에서도 접속 확인

## 3. 소셜 로그인 제공자 등록 — 쓰는 것만
각 콘솔에서 앱 등록 후 **키를 서버 환경변수에 추가**하고, **콜백 URL을 정확히 등록**하세요.
(안 채운 제공자의 버튼은 그냥 400 반환 — 이메일 로그인은 설정 없이 바로 됨)

| 제공자 | 발급처 | 서버 환경변수 | 콘솔에 등록할 콜백 URL |
|---|---|---|---|
| 카카오 | developers.kakao.com → 내 앱 → REST API 키 | `KAKAO_CLIENT_ID` | `https://내서버/auth/kakao/callback` |
| 구글 | console.cloud.google.com → OAuth 2.0 클라이언트 | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `https://내서버/auth/google/callback` |
| 네이버 | developers.naver.com → 애플리케이션 등록 | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | `https://내서버/auth/naver/callback` |
| 애플 | developer.apple.com → Identifiers | `APPLE_CLIENT_ID`(Services ID), `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY`(.p8 내용, 줄바꿈→`\n`) | `https://내서버/auth/apple/callback` |

- **애플**: Services ID + **Sign in with Apple Key(.p8)** 발급 필요. **https 실도메인만 허용**(localhost 불가).
- 각 콘솔의 `REDIRECT_URI` 환경변수도 실제 배포 도메인으로 맞추세요(기본값은 localhost).

## 4. 앱 아이콘 (거의 끝남)
- 기본 아이콘/스플래시는 `assets/` 에 생성돼 있음. 바꾸고 싶으면 같은 파일명으로 덮어쓰기.
- 로컬에서: `npm i -D @capacitor/assets && npx capacitor-assets generate`

---

## 5. Capacitor 네이티브 프로젝트 생성 (내 PC에서)
> 클라우드에선 불가. **Android SDK / Mac** 있는 로컬에서.
1. `capacitor.config.ts` 의 **`appId`** 를 본인 것으로 변경(예: `io.github.<깃헙아이디>.budget`) — ★출시 후 변경 불가
2. 앱 빌드용 서버주소 주입: `cp .env.app.example .env.production` → `VITE_API_URL=https://내서버주소`
3. ```bash
   npm install && npm run build
   npx cap add android          # Android Studio 필요
   npx cap add ios              # ★Mac + Xcode 필요
   npm run cap:sync
   ```

---

## 6. Android 서명 & AAB (내 PC에서)
> 상세 클릭 순서는 `docs/모바일-앱-출시-가이드.md` 5단계.
1. **keystore 생성**(Android Studio: Build → Generate Signed Bundle → Create new)
   → `.jks` 파일 + 비밀번호 2개 + alias를 **2곳 이상 백업**(잃으면 업데이트 영구 불가)
2. **AAB 빌드** → `app-release.aab` 파일 확보
3. 업데이트마다 `build.gradle` 의 `versionCode` +1

---

## 7. iOS 빌드 (Mac에서)
1. `npx cap open ios` → Xcode
2. Signing & Capabilities → Team 선택, Bundle ID = `appId`
3. **Product → Archive → Distribute → App Store Connect → Upload**

## 8. 스토어 등록 & 심사
### 8-1. 개인정보처리방침 (양 스토어 필수)
- 수집 항목(거래내역·이메일), 보관기간, 삭제절차, 암호화(HTTPS) 명시한 페이지를 웹에 게시.
  (노션 공개페이지·GitHub Pages 무료로 가능)

### 8-2. Google Play
1. 앱 만들기 → 스토어 등록정보(스크린샷·512 아이콘·소개글)
2. **데이터 보안 양식**: 재무정보 수집·암호화·삭제가능 사실대로
3. ★**비공개 테스트**: 개인 계정은 **테스터 12명 이상 × 14일** 필수 → 이후 프로덕션 신청
4. 심사 1~7일

### 8-3. Apple App Store
1. App Store Connect → 신규 앱 → 정보·스크린샷·앱 개인정보 라벨
2. **애플 로그인 이미 구현됨**(규정 4.8 충족)
3. ★**심사용 데모 계정**(이메일/비번) + 샘플 엑셀 사용법 메모 제공
4. TestFlight로 가족 먼저 테스트 → 심사 제출(24~48h)
